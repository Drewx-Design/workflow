The first approved compile accounts for 96 of the 143 operations.

The useful result is that the [ranking policy](../sorter/METHOD.md) reached the board through checked writes. Whether it produces better priorities is still unmeasured. Most runs ended partial; the latest completed run in this window stopped at a model account usage limit. Timeouts, seat startup delays, and growing journal replay cost also interrupted operation. Fixes have been made, but sustained unattended reliability still needs observation. Zero writes alone does not tell us whether a run was healthy, blocked, or had nothing to change.

## How this was checked

The sorter adoption timestamp was read from its control record. Run IDs and action IDs were deduplicated directly from the journal; only `confirmed` action outcomes were counted. Intake counts were reproduced from GitHub issue bodies containing the exact source marker. Cleanup's final dispositions and held totals were checked against its journal and rendered reports. The private evidence receipt retains file hashes and locators; raw issue text, worktree paths, and journals are not published.

These are owner-maintained records. Readers can inspect the public implementation and method, but cannot independently reproduce the private operating totals from this repository alone. Future records should bind deployed code revisions to each run and measure operator intervention as well as output.
